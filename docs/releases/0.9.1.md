# 0.9.1 角色像员工：项目 + 记忆

0.9.0 的角色只是「执行工具 + 模型 + 一段准则」，本质是一张派活配方：每次都从零开始，干过什么、被指出过什么都不留。这一版把它往「员工」推进一步：

```
员工（角色）= 职责 + 执行工具 + 模型 + 准则 + 可用工具声明 + 记忆
项目        = 名字 + 项目说明/约定 + 默认配置
配置        = 电脑 + 目录 + 优先级 + 验收模板（工位）
记忆        = 挂在「员工 × 项目」上，派活时自动带上
```

## 为什么要多一个「项目」

角色不应该绑死在一个工位上。同一个「后端实现」可以今天做 AgentHub、明天做另一个仓库——但它在这两个项目里积累的经验不一样，项目约定也不一样。

所以拆成两层：

- **项目说「这是什么」**：技术栈、约定、不能碰的东西、默认用哪套配置。这些是项目属性，换谁来做都成立。
- **员工记「我在这个项目上学到了什么」**：某个接口命名习惯、某个坑踩过一次、某条验收标准被打回过。

派活时选中项目，项目说明和该员工在这个项目上的记忆一起下发；没选项目就只带跨项目的通用经验。

## 记忆怎么来的

两条路，都能在角色卡上看到和删掉：

1. **手写**：设置页 → 角色 → 记忆 → 写一条，可以选「通用」或指定项目。
2. **打回自动沉淀**：验收时把某个检查项判为不通过并写了原因，这条原因会自动记进「该员工在这个项目上的经验」（`source=review`）。同一个原因再次出现不新增条目，只加权重。

记忆条目不是一坨长文本，而是可枚举、可编辑、可删除的单条经验，带着来源、出现次数、被用过几次。这样错的经验能删掉，过时的能改，而不是把一份越来越长的 prompt 越堆越乱。

## 注入顺序与预算

派活时拼成一段系统提示（走 0.9.0 已有的 `instructions` 通道）：

```
【角色】名字 · 职责
【准则】角色上下文
【项目】项目名
【项目背景】项目说明
【已知经验】
- 项目内经验（权重高的在前）
- 通用经验
```

- 总预算 5000 字。准则最多 2000、项目说明最多 1500，剩下的留给记忆；记忆按「项目内优先 → 权重高优先 → 用得少的优先」挑，装不下就少带几条。
- 被带上的记忆会累加 `uses` 和 `lastUsedAt`，所以下次会优先轮换到还没用过的经验，不会永远只带同几条。

## 界面变化

- **设置页 → 角色**：新增「职责」「可用工具」两个字段；每张角色卡多了「记忆」按钮，展开后按项目显示经验、可手写可删。
- **设置页 → 项目**（新）：项目名、项目说明、默认配置；显示有多少任务挂在这个项目上。
- **任务详情 → 执行设置**：多了「项目」下拉；选中后下面一行提示这个项目的说明摘要，并说明派活会带上项目背景与该项目记忆。任务没挂配置时，选项目会顺带用它的默认配置补齐电脑 / 目录（已填的字段不覆盖）。

## 可用工具只是声明

角色上的「可用工具」不会真的改变执行端权限——Claude / Codex 自带工具集，权限由执行工具和那台电脑决定。这个字段的作用是把职责边界写清楚、派活前能看见。真要限制，得在执行器侧下发 `--allowedTools` 之类的参数，那是另一个版本的事，而且 Codex 没有等价物。

## 验证

- 新增 `test/projects.test.ts` 4 个用例：项目增删改查与同名拒绝、任务挂项目且删项目后回到未归属、项目默认配置在派活时兜底（含项目说明随 `run.start` 下发）、越权引用别人的项目被拒。
- 新增 `test/memories.test.ts` 6 个用例：记忆增删改查与按项目筛选、同内容只加权重、派活注入顺序（项目经验排在通用经验前）与用量计数、没选项目时不带别的项目经验、验收打回自动沉淀且重复只加权重、删角色/删项目的级联清理与越权拒绝。
- 全量服务端测试 127 个用例（新增 10 个）连跑五遍全绿；前端 `tsc --noEmit` 与 `vite build` 通过。

## 顺带修掉的两个启动期竞态

加测试时把并发跑测试的偶发失败查到底了，两个都是真问题：

1. **启动回填撞上并发删账号会打挂服务**：`session_activity` 的一次性回填从 `messages` 里 `SELECT` 再插入，如果这期间有账号被删（`ON DELETE CASCADE`），插入会触发外键报错，整个迁移失败 → 服务起不来。现在把回填当尽力而为：只吞外键冲突（`23503`），其他错误照常抛。
2. **测试账号邮箱会撞**：`test/helpers.ts` 用毫秒时间戳生成邮箱，两个测试进程在同一毫秒启动就撞 `users_email_key`，表现是该文件整个用例被 `cancelledByParent`（不计入失败，容易误以为全绿）。现在时间戳后面加了随机后缀。

第 2 条只是测试脚手架；第 1 条在生产里也会发生——多实例部署时正好有人在删账号，就可能有一个实例起不来。

## 已知限制

- 记忆只在**新开**派活时注入。在原会话里续聊不会重新拼装系统提示（和 0.9.0 的上下文限制同源）。
- 挑记忆是规则排序，不是语义检索：按项目、权重、用量挑，不做「这条和当前任务相关吗」的判断。条目多了以后可以再加语义筛选。
- 项目说明和记忆都算在 5000 字预算里，写太长会挤掉经验条目——这是有意的取舍，避免提示词无限膨胀。
- 角色还没有「履历」视图（完成率、被打回次数、平均时长）和「收件箱」（这个员工手上还有哪些活），这些字段已经具备，留到下一版做角色工作台。
