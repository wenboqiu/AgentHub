# 0.11.17 角色 / 项目设置分两级，模型交给项目经理代挑

设置里的「角色」和「项目」不再把表单摊在列表里，同时补上「模型谁定」这块一直空着的地方。

- **设置分两级**：角色、项目的列表只负责浏览和入口，每行一条摘要，点进去在下一级页面编辑；新建也走同一个详情页，建完不跳走、直接变成它的详情页，可以接着补记忆 / 配目录，返回键逐层退（详情 → 列表 → 设置首页）。
- **两个入口同一套字段**：新增 `RoleFields`，角色详情页和「让助手建」的草稿卡渲染完全相同的字段——角色名 / 职责 / 执行工具 / 模型 / 可用工具 / 项目经理 / 上下文。草稿卡原来缺的「项目经理」（含管哪些项目）补上了；角色名与执行工具必填，去掉了「未指定」这种半成品选项，模型仍可留空。助手只是整理字段，项目经理这种组织安排不猜，由人在草稿卡上勾。
- **模型未指定时由项目经理代挑**：角色没写模型，派活那一刻按任务复杂度在该工具的模型清单里挑一档——说明字数、清单条数、要动的目录数、边界写得多细、优先级，以及「重构 / 迁移 / 架构」这类重活词加分、「文案 / 错别字」这类小活词减分；≥5 重档、≤1 轻档、其余常规。claude 三档是 haiku / sonnet / opus，codex 是 gpt-5.6-luna / gpt-6.1-sol / gpt-6.1-sol；zcode / codebuddy 没有可信清单，落回执行端默认。角色自己写了模型就听角色的。手动派发、项目经理自动派发、离线排队后投递用的是同一个结果。
- **挑了谁、为什么，记下来**：执行记录新增模型与理由两列（`runs.model` / `runs.model_note`，排队表同样存理由）。任务页派发后直接显示一句「为什么用这个模型」，验收摘要的「最近执行」带模型（`成功（sonnet）`），角色列表里没写模型的标「模型代挑」。
- **修项目配置的电脑下拉**：电脑清单是异步加载的，原来用「名字不在清单里」判断手填模式，加载完成前会把每条配置卡进手填输入框；现在手填只由「其他电脑…」触发，清单里没有的机器名作为临时项显示。

服务端有改动：`runs` 与 `task_dispatch_queue` 新增列（启动自动迁移）、派发响应新增 `model` / `modelNote`、助手草稿白名单新增 `manager` / `managerProjects`，**先升服务端再升客户端**。向下兼容：老服务端只是忽略新字段，新客户端不会报错，只是「代挑模型」不生效；老电脑端照旧忽略模型字段（会提示角色降级）。
