# 0.11.5 任务单收成一个入口，只读会话的回复不再迟到

对话页不再展开任务单全文；本版服务端也有改动（只读会话收尾排队），两端一起升最稳妥。

- **对话页只留一个入口**：一条会话跑完，消息流末尾只出现一行 `任务单 · 1 份待确认`（都处理完显示「都已处理」，多份在右侧标 `共 N 份`），点进去才看全文。过去任务单整块铺在对话下面，长会话里一屏全是单子、最新回复被顶到看不见。
- **任务单详情页**：顶部「返回」回到会话，右上角图标一键跳回这条会话；一行来源说明 `来自「会话标题」（Agent · 项目） · 1 份待确认 · 共 2 份`。待确认的排前面、已处理的排后面（已确认/不用了仍留一行结论），卡片内容不变：执行人、项目、从哪开始、要做什么、验收要点、优先级、执行边界、证据，以及「确认并派发 / 只建任务 / 让项目经理重写 / 忽略」。
- **只读会话收尾顺序**：WorkBuddy 这类会话的正文只在电脑上，服务端收到跑完事件时先向电脑端要一份最新正文入库、再攒任务单，所以任务单不会再比这一轮的回复先出现，标题也摘自最新回复。同步要等电脑端回话（最多 10 秒），单独排队，不拖慢事件上报，也不会几十个一起占满数据库连接。
- **客户端自动刷新**：服务端同步完会通知客户端，正在看的会话直接重载消息，不用手动点刷新。

任务单入口与详情页在客户端；收尾顺序与排队在服务端，服务端需重启后生效。
