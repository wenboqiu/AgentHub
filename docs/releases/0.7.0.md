# 0.7.0 Thread 统一事件流

把「任务」升级为 Thread——以任务为锚点的**统一事件流**（思路来自 DeepSeek Super-agent：Session 应当是系统实现细节，用户面对的应该是一条连续的工作线）：关联会话的对话消息、执行记录、时间提醒、投机摘要，全部按时间合并成一个视图。

## 服务端

- `GET /threads/task/:id?limit=200`：聚合返回 `events[]`，四类事件：
  - `message`：关联会话的消息（角色 + 文本节选）；
  - `run`：挂在任务上或发到关联会话的执行记录（状态 / 错误）；
  - `reminder`：任务的开始 / 截止提醒（含已处理状态）；
  - `digest`：投机摘要（验收摘要的最后回复节选 / 失败上下文的错误信息）。
- 纯聚合读，不迁移数据、不改变任何现有 API；按时间倒序，默认 200 条上限。

## 客户端

- 任务详情页新增「时间线」区块：打开详情时拉取，任务更新后自动刷新，也可手动刷新；最多显示最近 50 条。
- 消息类事件带角色标签（用户 / 助手 / 工具 / 授权），执行与摘要类事件弱化显示。

## 边界

- 时间线是打开详情时的快照 + 任务变更时刷新；会话消息的实时增补仍走原详情页（后续版本可把 WS 消息增量插入时间线）。
- 未挂任务的会话暂不进入 Thread 视图（它们在会话列表有自己的完整详情）。

## 测试稳定性修复（本次顺带）

- Watchdog 卡死扫描加反连接（排除已领取的会话），`watchdog_state.arm_key` 迁移为 timestamptz 以精确比对 event_at；修复并行测试时历史积压会话把新会话挤出处理窗口的问题。
- 限流 `--test-concurrency=4`（此前默认并行 10 个测试进程打同一个 Postgres，基线时期就存在毫秒级定时器用例的偶发超时）。
- 清理本地开发库中历史崩溃测试残留的账号与 running 会话。
