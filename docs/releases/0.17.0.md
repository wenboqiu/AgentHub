# 0.17.0

看清「哪台电脑在不在」和「agent 自己做了什么主」：设置里多了设备页，Codex 会话被别的客户端占着时发消息前就能看见，验收页把 agent 自己拍板的决定按「难逆在前」列出来。

## 新增

- **设备页**：设置 → 账号 →「设备」把 `/machines` 平铺出来，按「在线 / 没开远程执行 / 离线」三态分组（只监听不算在线），每台给最近活动时间与上报过的工具，并标出本机，10 秒轮询刷新；入口摘要直接写「2 台在线 · 1 台离线」。分组与汇总逻辑抽成 `src/lib/devices.ts` 纯函数，配了 5 例测试。
- **派活约定：agent 自己拍板并留记录**：派活指令里加了一条约定——遇到岔路不打断地自己拍板，回复里单独写一行「决定：X；原因：Y；可逆性：易/难」；可逆性为「难」的操作（删数据、对外发布、花钱、动授权范围外的东西）不许自己拍板，先停下来问。验收页把摘出来的决定汇总成一段，**难逆的排最前**并打「难逆」标记，方便重点复核。
- **Codex 会话被占用提前提示**：Codex 的 thread-store 不允许同一 thread 两个活跃 writer。以前从 AgentHub 发消息只会失败（`thread ... already has an active writer`），现在会话页每 5 秒探测一次 `~/.codex/thread-writer-locks/<threadId>.lock` 上的排他锁，被别的客户端占着时输入框上方直接出警示条；AgentHub 自己在跑这条会话时不提示（锁是自己握的）。发送失败时也附上了可读的处理指引。

## 升级

服务端有改动（派活指令加「决定」约定、`/tasks/:id/review` 返回多一个 `decisions` 字段），**先升服务端再升客户端**。数据库无迁移，旧任务的验收页直接按老回复解析，摘不到决定就是空列表。
