# 0.8.3 项目配置：执行环境 + 检查项模板

派活时要填三格（执行工具、电脑、项目目录），验收时又要重新想「这个项目该看哪几项」。0.8.3 把它们收成一个有名字的东西：**项目配置**。

## 一条配置是什么

```json
{ "name": "AgentHub 前端", "agent": "claude", "machine": "台机",
  "cwd": "D:/Work2/AgentHub", "priority": "high",
  "checklist": ["tsc 通过", "vite build 通过", "手动点一遍主流程"] }
```

它是**执行环境 + 验收标准**，不是人格。AgentHub 改不到 Claude Code 的 prompt，也不该去改，所以配置里没有 system prompt、没有记忆、没有工具集——那些属于执行端。这里只回答三个问题：用哪个 agent、在哪台机器哪个目录跑、这个项目的交付要过哪几关。

## 怎么用

```
设置 → 项目配置 → 新建配置
任务详情 → 执行设置 → 项目配置 → 选一个
```

选中之后：

- **空着的字段自动补齐**（执行工具 / 电脑 / 项目目录），**已经填过的一律不覆盖**——你在任务上做的具体调整永远优先。
- **检查项模板并入任务清单**，模板项带固定 key（`tpl-<文本哈希>`），清单随即自动同步成验收检查项（0.8.1 的机制），不需要额外一步。
- **换配置时模板项跟着换**：上一条配置留下、但没勾选的模板项会被移除；**已勾选的保留**，手工加的清单项一律保留。
- 建任务时没显式指定优先级，跟随配置的默认优先级。
- 派活（`POST /tasks/:id/start`）时如果任务上的目录 / 工具还空着，用配置兜底——配置后改的也能生效。

## 删配置

任务上的执行字段全部保留，只是不再指向任何配置（`profile_id` 置空）。删除时会把这些任务的更新推给客户端，界面上的配置名立刻消失。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/profiles` | 列表，带每个配置下的任务数 |
| POST | `/profiles` | 新建；同名返回 409 |
| PATCH | `/profiles/:id` | 局部更新；只传要改的字段 |
| DELETE | `/profiles/:id` | 删除；引用它的任务置空并推送 |

任务侧新增 `profileId` 字段，`POST /tasks` / `PATCH /tasks/:id` 都接受它（`null` 表示取消关联）。

## 校验

- 配置名 1–60 字符、同账号内唯一
- 检查项模板最多 30 条、每条 1–500 字符、**不允许重复**（重复项会让清单出现两条同样的检查）
- agent 只接受 claude / codex / doubao / workbuddy 或空（界面只列 claude / codex——另两个只做状态监听，放进默认值只会让派活报错）
- 只能引用自己的配置，别人的返回 404

## 升级与验证

先升级服务端再升级客户端。服务端启动时自动建表（`profiles` + `tasks.profile_id`），老任务 `profile_id` 为空，行为不变。

- 服务端 **100 个用例全绿**（新增 `test/profiles.test.ts` 7 个：CRUD 与同名冲突、建任务补字段与模板变检查项、显式字段不被覆盖、换配置的保留规则、删配置后字段保留、越权引用、派活时目录兜底），全量三连跑无失败
- 前端 `tsc --noEmit` 与 `vite build` 通过

## 已知限制

- 配置的改动不会通过 WebSocket 广播，打开任务详情时才拉最新列表（配置改动不频繁，先不做推送）。
- 换配置不会自动调整任务的优先级：优先级只在建任务时跟随一次，之后是任务自己的属性。
