# 0.9.9 一句话建角色，出包自动上传

这一版把「建角色」从填表单变成说人话：设置 → 角色页右上角「让助手建」，用一句话描述要什么样的人，电脑端的 agent 整理成一份草稿，改完点确认才落库。同一版还补上了出包后的分发：`tauri build` 完自动把安装包推到 Cloudreve。

## 角色助手

角色表单有九个字段（工具、模型、职责、上下文、可用工具、默认配置……），第一次建的时候大多不知道怎么填。助手做的就是把这层翻译掉：

```text
「要个负责前端实现的，用 Codex，改完跑 tsc」
  → 草稿：名字 / 职责 / 执行工具=codex / 模型 / 可用工具 / 上下文
  → 确认（或就地改）→ POST /roles
```

- **不新建模型通道**：服务端一直没有模型凭据，助手直接复用派活链路，把这一问投给已登录的 Claude / Codex / ZCode；
- **首条消息带契约**：只回一个 JSON、已有角色清单（防重名）、当前配置清单（电脑 / 目录 / 项目配置 id），原话附在后面；
- **追问就是续聊**：「名字改成前端实现，模型 sonnet」在原会话里补一句「照旧只回 JSON」，重出一版草稿；
- **确认才写库**：草稿卡上每个字段都能改，点「创建角色」走的是和手填表单同一个 `POST /roles`，重名、上限、字段长度校验完全一致；
- **解析不出来不猜**：`parseDraft` 三级抠 JSON（代码块 → 整段花括号 → 整行），失败就保留原文并给一个「让它重说一遍」。

草稿按「哪条回复」挂（`assistant_drafts.message_id` 唯一），确认或丢弃后不能再处理。一个账号只保留一条助手对话，换工具或换电脑就「重新开始」。

## 几个实现上的坑

- **待定会话会改名**：派活时先建 pending 会话，执行器接手后 `renamePendingSession` 会改 sessions / runs / messages 的 id。用 `last_run_id` 认「这轮是不是助手的 run」，不依赖 session id。
- **历史快照会重排消息 id**：助手会话不同步原生历史——快照整段替换消息后草稿会变孤儿。完成通知也按标题前缀 `角色助手：` 静音，人就等在面板前。
- **离线先判断**：`/assistant/start` 原本先建 thread 再查电脑在线，电脑离线时会先把旧对话和草稿删掉。改成先查 `executors.has`。

## 出包自动上传

`npm run release` = `tauri build` + `node scripts/publish-cloudreve.mjs`，把 NSIS 安装包通过 WebDAV 推到 Cloudreve v4 的 `my/Artifacts`：

```text
v0.9.9/AgentHub_0.9.9_x64-setup.exe   # 归档
latest/AgentHub_0.9.9_x64-setup.exe   # 固定命名，每次覆盖
```

`--check` 只验账号和目录、`--dry-run` 只找产物不联网；凭据走环境变量或 `.env.local`（`*.local` 已忽略），模板见 `.env.example`。401 会直接提示「WebDAV 专用密码 ≠ 网页登录密码」。

## 限制

- 电脑得开着 AgentHub，且该 agent 已登录；一次问答十几秒（CLI 冷启动），没有流式输出，面板按 run 状态轮询；
- 目录必须在这台电脑上真实存在；助手只在里面「想事情」，不读写文件；
- 老电脑端（不支持 `role-v1`）不受影响——契约只走消息正文，模型与上下文仍靠服务端随派活下发。

## 升级

服务端有改动（两张新表 + 六个接口），**先升服务端再升客户端**。电脑端执行器不用换：它收到的还是普通的一条消息。
