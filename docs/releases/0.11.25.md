# 0.11.25

修复回复截断；运行结束的汇总行显示实测模型与积分用量。

## 修复

- **agent 回复超过 4000 字被截断**：三层上限同步提到 16000 字——
  - 执行器 `runner.rs` 的 `TEXT_MAX`（流式回复 / 正文上报的统一截断）；
  - 服务端 `db.ts` 的消息入库（`insertMessage`）、历史整段替换（`replaceHistory`）、事件正文（`appendEventMessages`）统一用新常量 `MESSAGE_TEXT_MAX = 16000`。三层必须一致，否则历史同步时会把长回复再截一次。DB 的 `text` 列本身无上限，无需迁移。

## 新增

- **结束汇总行显示实测模型**：Claude 的 result 事件自带 `model`，ZCode 从 `state.updated` 的 model 变更捕获，随用量事件上报；服务端只在 run 还没记过模型时填（不覆盖角色配的模型）。汇总行现在是「本次完成 · 用时 … · 模型 X · 输入 …」。
- **积分用量**：`Usage` 新增 `credits`，用量解析认 `credits/creditsUsed/points` 等字段（数字或字符串都行）；只有积分没有 token 数也算有效用量（积分制通道）。界面在花费后追加「· N 积分」，没有该字段就不显示。

## 验证

- `cargo test --lib`：149 通过（含新增 `usage_from_result_carries_model_and_credits`）。
- 服务端 / 前端 `tsc --noEmit` 通过；`npm test` 65 通过。
- **服务端需重新部署后，模型与积分的显示才会生效**（桌面端只影响截断修复与汇总行渲染）。
