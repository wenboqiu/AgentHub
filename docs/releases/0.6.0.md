# 0.6.0 Watchdog 卡死 / 反复失败检测

独立的检测回路（思路来自 DeepSeek Super-agent 的外部 Watchdog）：**只提醒、不干预**——执行在 Claude/Codex 手里，AgentHub 发现异常时升级给人处理。

## 检测项

1. **疑似卡死（stall）**：会话处于 `running` 且超过 45 分钟没有任何新事件（默认值，服务端可配）。长时间任务分多段跑时，每段只提醒一次；有新事件后重新武装。
2. **反复失败（abort-spree）**：同一会话 2 小时内第 3 次中断时提醒一次，同窗口内不重复；会话恢复 running 即清零计数。

## 行为与边界

- 服务端默认每 60 秒检查一次；推送 WS `watchdog` 消息，桌面弹系统通知，Android 前台服务弹通知（「可能卡住了」/「反复失败」）。
- 检查回路**不进**事件处理串行链（独立查询 + 幂等领取，不与事件流争抢）；卡死提醒的幂等标记落库（`watchdog_state`，按 会话×event_at 记账），服务重启不会重复轰炸。
- 首次上线时遗留的陈年 running 会话：只看最近 7 天、每批最多 50 条，分批消化不造成突发；提醒一次后不再重复。
- 反复失败计数是内存态，服务重启清零（可接受：错过一次连击提醒的代价远小于持久化状态的复杂度）。
- 服务端可配：`watchdogIntervalMs` / `stallAfterMs` / `abortSpreeCount` / `abortSpreeWindowMs`。
