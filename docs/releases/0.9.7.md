# 0.9.7 ZCode 能派活了

0.9.6 把 ZCode 接进监控列表，但只看得见、使不上——它的状态能提醒，任务却派不进去。这一版补上执行通道：ZCode 成为和 Claude / Codex 平级的执行工具。

## 派活怎么走

ZCode 桌面端自带 CLI（`resources/glm/zcode.cjs`），`app-server --stdio` 起一个 ZCode Protocol 进程。执行器按 run 起进程：

```text
session/create → provider/refreshRegistry → provider/updateAccountConfig
  → session/subscribe → session/send → 事件流 → session/stop（可选）
```

- **新会话**：`session/create`（workspace = 项目目录）→ 发消息；
- **续聊**：`session/resume {sessionId}` → 发消息；
- **停止**：`session/stop`，不走杀进程；
- **授权**：`interaction/requestPermission` 反向请求转成 AgentHub 的审批卡片，手机点允许／拒绝，30 分钟不处理按拒绝；
- **读历史**：会话文件里就有完整消息，直接读。

## 裸跑 CLI 要补的三件事

桌面端之所以能跑，是因为 Host 在背后做了三件事，执行器全部照做：

1. 指向内置 provider 配置（`ZCODE_BUILTIN_PROVIDER_CONFIG_FILE`）；否则 CLI 报「无法定位 Built-in Provider Config」；
2. `provider/updateAccountConfig` 下发账号权益——裸跑时 builtin 模板里所有账号 provider 都是 `entitled: false`，registry 为空，send 会报「Select a model」。基础版本 `basedOnZCodeBuiltinRevision` 从 CLI 日志的 `provider_registry.ready` 里动态读取（值在 `context.configRevision`，是被字符串化的数组），不硬编码，ZCode 升级也不会失效；
3. 响应 `interaction/requestProviderRuntimeHeaders`，注入 Project Access Token：读本地 `~/.zcode/v2/credentials.json`（`enc:v1:` 的 aes-256-gcm 密文，密钥按平台 + 用户名派生）→ getCustomerInfo → api_keys → access_tokens。token 只在内存里传给 CLI，不写日志。

## 踩到的两个坑

- **帧不能带 `jsonrpc`**：ZCode 的四种帧是 strict schema（`{id, method, params}` / `{id, result}` / `{id, error}` / `{method, params}`），多一个字段整帧被拒，报 `Invalid ZCode Protocol message`。Codex 用的应答构造器带 `jsonrpc: "2.0"`，ZCode 另写了一个。
- **完成信号不在 `session/event`**：这一版 CLI 不发 `turn.completed` 的正文，回复只在 `model.streaming` 的 `text_delta` 增量里，终止态在 `computer-use/operation-event`（`turn-completed`）和 `v4/telemetry/event`（`turn.terminal`）。执行器三路都认，正文用增量累积。

## 限制

- 不支持按回复分叉（服务端明确报「暂不支持按回复分叉」）；同目录新开和续聊正常；
- 派活时不能附图（`session/send` 的附件格式还没对上，明确拒绝而不是悄悄丢）；
- Agent 的提问（`interaction/requestUserInput`）还不能在 AgentHub 里作答，会自动取消并提示；
- 默认模型 GLM-5.3 + 账号默认 provider，角色里写 `providerId/modelId` 可覆盖；
- 需要本机装好 ZCode 并已登录；ZCode 的 CLI 协议是桌面端私有协议，升级后可能要补适配。

## 升级

服务端和客户端都要换：服务端放开 zcode 的派活／续聊／读历史限制，客户端补执行器。先升级服务端再升级客户端。

## 验证

- Rust 104 个测试通过（新增 ZCode 协议响应构造、日志 revision 解析、凭证直通、model 解析）；
- **真机端到端**：`AGENTHUB_ZCODE_E2E=1 cargo test --lib zcode_dispatch_end_to_end -- --ignored` 真实跑一轮——建会话 → 注入 token → 发「只回复 OK1」→ 收到 `OK1` → `done`，36.6 秒，消耗约 24k input tokens；
- 服务端与前端 `tsc --noEmit` 通过。
