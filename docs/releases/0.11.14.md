# 0.11.14 Windows 上接单跑通

WorkBuddy 自己接活（codebuddy CLI 执行任务单）这套在 Windows 上真正可用：修掉了三处只在 Windows 会炸的路径问题，外加一处会把登录态劫持走的环境污染。

- **task-run 启动即崩修复**：模块路径用 `fileURLToPath` 解析，Windows 下 `import.meta.url` 会产生 `/D:/...` 双盘符路径，脚本一跑就 `MODULE_NOT_FOUND`。
- **CLI 定位补全**：`workbuddyCli()` 候选补上 Program Files 两处；本机装在别的盘时用 `~/.agenthub/watcher/config.json` 的 `workbuddyCli` 显式指定。
- **产物路径跨盘不串位**：Windows 的 `/tmp` 会落到当前盘根目录（cwd 在 D: 就是 `D:\tmp`），改成系统临时目录。
- **执行器环境消毒**：spawn 前剥掉宿主注入的 `ACC_PRODUCT_CONFIG*` / `WORKBUDDY_RESOURCES_PATH` / `NODE_OPTIONS`——WorkBuddy 会话内启动时，这些变量会把 CLI 的产品身份劫持到 `workbuddy-desktop`（token 为空的桥接文件），认证必挂。
- **Windows 登录方式**：内置 lite-wb 复用不了桌面登录态（桥接文件里 token 为空，真实凭据走加密适配器），要用 npm 完整版 CLI 独立登录一次：`npm i -g @tencent-ai/codebuddy-code` → 终端跑 `codebuddy` → `/login`。

另：气泡图待处理会话支持单个已处理。

实现见 [任务单执行](../task-watcher.md)。
