# 0.5.9 投机预摘要与失败预诊断

任务进入「待验收」或执行失败时，服务端**在后台提前**准备好一份结构化摘要（投机执行：先备好，点开即见），用户打开任务详情不用再开终端翻记录。

## 行为

- **验收摘要**：关联会话完成、任务进入待验收时生成。内容包括：主要会话（标题/工具/项目）、已同步的消息数、最后一条助手回复节选（500 字内）、最近 3 次执行记录。任务回到进行中再次完成时自动重新生成。
- **失败上下文**：run 失败时生成。内容包括错误信息与失败前最后 5 条消息（工具调用 / 回复节选），直接显示在任务详情里。
- 会话还没有同步过历史时，摘要退化为元信息，并提示去会话详情「加载电脑历史」看全文。

## 交互

- 任务详情页新增「预摘要」区块：失败卡片（红）在上，验收摘要卡片在下，可一键跳转关联会话。
- 摘要生成后通过 WS `task.digest` 实时推送到已打开的详情页；打开详情时也会主动拉取一次（`GET /tasks/:id/digest`）。
- 摘要缓存在 `task_digests` 表（每任务每类一条，任务删除即级联清理）。

## 边界与说明

- 摘要生成只读会话/运行数据并写自己的缓存表，不改变权限模型，不需要执行器在线。
- 摘要内容来自服务端已有的消息（远程控制的对话、手动刷新过的历史）；没同步过历史的会话没有正文可摘，属已知限制。
- 当前摘要为规则拼装（不是 LLM 生成）；`notify.ts` 的 Slow Path 接缝思路同样适用于未来接模型润色。
