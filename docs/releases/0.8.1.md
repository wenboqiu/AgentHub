# 0.8.1：验收检查项与证据链

灵感来自 LobeHub 的 Acceptance 实践（Agent 交付后自己跑一遍检查项、附证据，人整体通过或部分打回，打回原因沉淀为标准）。AgentHub 不跑被测产品，所以证据只从已有材料里取：**会话记录自动摘取 + 人工补充**，全程只读。

## 新增

**检查项 = 任务清单**
- 任务清单里的每一项自动成为验收检查项；清单改名跟着改，删除则移除。
- 已勾选的清单项初始为「通过」，其余待判定；判定结果不会被后续同步覆盖。
- 可以临时补检查项（手动项不会被清单同步删掉）。

**通过 / 打回**
- 每项可判「通过」或「打回」，打回可填原因，也可撤销回待定。
- 打回原因自动沉淀为**账号级标准**（同一原因只累加次数，不重复），任务详情页展示最近 5 条，作为下次交付前的自查清单。

**证据**
- 从关联会话的最近 200 条消息里自动摘取五类证据：文件变更、执行命令、测试结果、截图路径、错误日志。
- 进入待验收时随预摘要一起生成并缓存；没有缓存时按需抓取。
- 只提取，不解析、不执行；`node_modules`/`dist` 等构建产物和绝对路径不进证据。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/tasks/:id/review` | 检查项 + 证据 + 打回标准 |
| POST | `/tasks/:id/review` | 补一项检查（`{title}`） |
| PATCH | `/tasks/:id/review/:itemId` | 判定（`{status:'pending'\|'pass'\|'fail', note?}`） |

预摘要 `GET /tasks/:id/digest` 的 `review.evidence` 增加同结构证据数组。

## 数据

- `review_items`：按 `(user_id, task_id, item_key)` 唯一，清单项与人工项共存，`manual` 区分。
- `review_standards`：按 `(user_id, text)` 唯一，重复打回只累加 `hits` 与 `last_at`。

## 升级

先升级服务端（新表由迁移自动创建），再升级客户端。旧客户端不受影响。

## 验证

- 服务端 88 个用例通过（新增 `server/test/review.test.ts` 5 个：证据摘取、清单同步、打回沉淀、非法输入、账号隔离）。
- 前端 `tsc --noEmit` 通过。
