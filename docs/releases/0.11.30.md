# 0.11.30

任务单改两段式：会话跑完先给一行建议，人点了才展开完整任务单。Codex 通道的历史与生成图片也补回来了。

## 新增

- **任务单两段式（建议 → 任务单）**。会话跑完不再直接甩一张看不完的长单：
  - **建议**（`session_proposals.stage='suggest'`）：只出一行「类型 + 标题 + 执行人」，两个按钮「生成任务单 / 不用了」。标题仍是规则档从收尾语、失败现场、未完成项里摘的，几十毫秒，不叫模型。
  - **任务单**（`stage='draft'`）：点「生成任务单」（`POST /proposals/:id/draft`）才展开完整表单（说明 / 验收要点 / 执行边界 / 从哪开始 / 优先级），同时让项目经理用模型重写一遍，写好自动替换。
  - 发单（`kind=ticket`）和打回重做生成的单直接是任务单——它们本来就写明了要做什么。确认、忽略、撤回、「只留一张待确认」的行为不变。
- **Codex 生成图片**：新版 Codex 把图片生成事件从 `imageGeneration` 改成 `type:"Extension", kind:"image_gen.generation"`（`savedPath` 指向成品），现在能实时显示，也能在历史同步后留下来。

## 变更

- 会话跑完**不再自动**让项目经理细化。这一步只在人点「生成任务单」时发生：一次模型调用从「每条会话都跑」变成「人真正想看的单才跑」。
- Codex 历史**整读 rollout**（上限 512MB），不再按 4MB 截尾。图像生成技能会把 base64 写进 rollout 行里（单行可达数 MB），按字节截尾会只剩最后一条回复，重载后对话流只剩一句。
- 历史消息带 `images`（data URL，单张 8MB / 总量 48MB 预算），`replaceHistory` 落库 jsonb：会话刷新不再把图删掉。
- zcode 历史补 `images` 字段。

## 边界

- 建议阶段的质量取决于规则档：它只保证「做什么、谁来做」是对的方向，说明与验收要点要看模型那一步。电脑离线时点「生成任务单」仍能展开规则稿，只是没有重写，卡片上会说明原因。
- 建议阶段不写 `notes` 之外的长内容进界面，但库里仍留着规则稿——展开时先看到的就是它，等模型回来再替换。
- Codex rollout 整读对大文件有一次读取开销（实测 58MB 会话约 0.2s）；图片总量超预算的会话只留前面几张。
