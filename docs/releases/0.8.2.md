# 0.8.2 · 派活排队与失败回退

派活（`POST /tasks/:id/start`）之前是"一发子弹"：目标电脑离线就直接 409，任务停在待办，人得等它上线再手点一次。这一版把投递变成可靠的一步——**离线先入队，电脑上线自动派发**；同时修掉一个派发失败后任务卡在"进行中"的边角问题。

服务端先行升级，客户端后升级（旧客户端遇到离线电脑仍会自己拦住按钮，不会报错）。

## 电脑离线不再失败，改为排队

- `POST /tasks/:id/start` 在目标机器不在线时不再返回 409，而是把「派给谁、用什么 agent、哪个目录、第一条消息」原样入队，返回 `{ queued: true, task }`，任务状态保持 `todo`。
- 入队时把 agent / 电脑 / 目录同步写回任务，界面据此显示"这笔活瞄准哪台电脑"；取消排队不会清掉这些设置。
- 同一任务重复派发会覆盖上一次排队项（以最新一条消息为准），不会堆出两次投递。
- 任务新增只读字段 `queuedAt`（排队时间），由队列推导，不是 tasks 表的列。

## 电脑上线时自动投递

- 执行器连上服务端（`/ws?role=agent&machine=...` 登记完成）后，立刻按入队顺序投递该机器的排队项。
- 一次上线最多投递 **3 条**（`queueDrainLimit`），避免长时间离线后一次性喷出几十个会话；剩下的等下一次上线或下一轮清扫继续。
- 投递失败累计 `attempts`，连续 **3 次**（`queueMaxAttempts`）后放弃并写服务端日志，队列项被移除，任务回到"未排队"的可重试状态。

## 排队项会过期

- 存活 **24 小时**（`queueTtlMs`）。电脑一直不上线时，不能让一周后的一次上线把陈年派发全部放出来。
- 每 60 秒清扫一次（`queueSweepIntervalMs`），过期的队列项删除并向该账号推一次任务更新，界面上的排队标记随之消失。

## 派发失败时任务不再卡在"进行中"

`startSession` 是先提交事务（任务已改成 `doing`）再下发 `run.start`。如果电脑恰好在检查通过之后、发送之前掉线，原来的结果是：run 标 failed、临时会话 aborted，但**任务停在 doing 而没有任何运行**。现在会在失败分支里把任务退回 `todo`，会话挂接保留（失败记录和失败诊断仍挂在任务上，方便重派时对照）。

## 客户端

- 任务详情「执行」区块：电脑离线时按钮变成「排队等上线」，并提示"开始后会在它上线时自动派发"；不再显示"电脑端不在线"的拦截文案。
- 已排队时显示一行状态：`已排队 · 等 <电脑> 上线后自动开始（入队时间）`，带「取消排队」。
- 新接口 `DELETE /tasks/:id/queue` 取消排队。

## 接口与配置

| 项目 | 说明 |
|---|---|
| `POST /tasks/:id/start` | 在线返回 `{runId, sessionId, task}`；离线返回 `{queued: true, task}` |
| `DELETE /tasks/:id/queue` | 取消排队，返回 `{task}` |
| `queueTtlMs` | 排队项存活时间，默认 24 小时 |
| `queueDrainLimit` | 单次上线最多投递条数，默认 3 |
| `queueMaxAttempts` | 投递失败放弃阈值，默认 3 |
| `queueSweepIntervalMs` | 过期清扫间隔，默认 60 秒 |

## 验证

- 新增 `server/test/queue.test.ts` 5 个用例：离线入队且任务留在待办、上线自动派发并清空排队标记、取消排队与重复派发覆盖、在线直派不入队、过期作废。
- 服务端全量 **93 个用例**，连续两轮全绿（首轮有一次 admin 404 用例的环境抖动，与本次改动无关）。
- 前端 `tsc --noEmit` 与 `vite build` 通过。
- `tasks.test.ts` 两处断言随行为变更调整：离线派发由 409 改为 200 + 排队；发送失败后任务状态由 `doing` 改为 `todo`。

## 已知限制

- 排队项被过期或连续失败自动放弃时，**只更新任务状态，不单独发通知**。当前靠"排队标记消失"体现，下一步可以接入通知管线（`notify.ts`）做一次明确提醒。
- 排队只覆盖"点名某台电脑"的派发；如果任务没设电脑、而账号下有多台在线机器，仍要求先选定一台（行为不变）。
