# 0.8.0 点通知回到应用、日视图缩放

这一版把两条被动路径做成可操作：系统通知点了能落到具体条目，日历日视图能放大看细节；顺带把「项目目录」的校验从拦路改成护栏。

## 客户端

- **系统通知可点击跳转**。统一入口 `src/lib/desktopNotify.ts`：启动时注册一次 `onAction` 监听（插件只有注册后才会回报点击），通知用 `extra` 带上 `{kind, id}`，点击后由 App 决定跳到会话 / 任务 / 目标详情。
- 通知点击先把主窗口叫回前台：Rust 侧新增 `show_main_window` 命令，走 `unminimize + show + set_focus`，并在 Windows 上补一次强制前置（被托盘或系统通知唤起时，系统常拒绝抢前台）。
- 权限只问一次；被拒绝后下次再问（用户可能刚在系统设置里改过）。通知发送失败一律静默，不影响主流程。
- **日历日视图支持缩放和平移**。日视图右上角工具条：`‹ ›` 半窗平移，`＋ －` 在 24 / 12 / 6 / 3 小时之间切换；缩放以当前窗口中心为锚点，内容不跳。数据仍按整日取，缩放不重新拉取。
- 刻度随时长变细（24h→3h、12h→2h、6h→1h、3h→30min），网格线用 `--tf` 与坐标轴对齐；计划条和会话段完全落在窗口外时不画，避免边缘出现误导性细条。

## 桌面端（项目目录校验）

- 白名单改为**反默认**：`allowedRoots` 为空 = 不限制目录（只拒绝空路径和 `..`），填了才按原来的前缀匹配。空名单不再等于全部拒绝。
- 新增目录存在性检查：盘符或路径写错时直接报错，不再让子进程起不来。
- 失败原因分成四档，各给可操作文案：目录为空 / 含 `..` / 不在白名单（附当前白名单原文）/ 目录不存在（检查盘符和路径）。`run.status.error` 会经 `sessions.summary` 和任务失败摘要一路显示到手机。

## 边界

- 白名单是防手滑，不是沙箱：跑起来的 agent 用 Bash 或写文件仍能碰到白名单外的路径，真正的边界是账号和 HTTPS。
- Windows 上只有通知还在屏幕上时点击会被回报；已收进通知中心的历史通知系统不再回调。
- 都需要重新构建桌面端才生效。
