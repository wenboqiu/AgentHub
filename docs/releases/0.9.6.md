# 0.9.6 ZCode 也进监控列表了

AgentHub 此前只认 Claude、Codex、豆包和 WorkBuddy。如果你同时在用 ZCode（Z.ai 的编程工作台，桌面 / Web / 终端三形态），它的会话跑完或挂掉时 AgentHub 没有任何反应——现在有了。

## 监听什么

与 WorkBuddy / 豆包同级的**只读状态监听**：

- 会话列表展示 ZCode 会话的标题、所属项目目录、运行中 / 完成 / 失败状态，完成和失败照常触发桌面 / 手机提醒，处理过的自动或手动消掉；
- 「跳转」切到 ZCode 窗口（按 `ZCode.exe` 找可见窗口），不能定位到具体会话；
- 时间轴上有对话跨度：采集器把会话里每条消息的时间戳聚合成 5 分钟活动桶随事件上报，和 WorkBuddy 的跨度同一条路。

## 为什么这一版比 WorkBuddy 省心

WorkBuddy 的 transcript 没有会话级状态字段，完成要靠「尾部结构 + 静默窗口」推断，正常结束比实际晚 20–60 秒。ZCode 不一样：`~/.zcode/v2/sessions/<工作区哈希>/sess_<uuid>.json` 里的 `meta.status` 由 ZCode 自己维护（`running` / `completed` / `error`，从安装包内的 schema 确认过），映射为 running / done / aborted，**状态一变立刻上报**，不用猜、不会晚。

## 不做什么

- 不提供完整对话正文、等待授权、远程发消息、新建或分支——ZCode 没有 hook，也没有可调用的 CLI/IPC 通道，服务端对 zcode 会话的这些操作一律返回 409；
- 任务的执行工具仍只有 Claude / Codex，ZCode 不能被派活。

## 已知边界

- `~/.zcode/v2/sessions` 的目录结构与 `meta.status` 枚举没有对外承诺，ZCode 升级后可能改变，届时采集会失效需要重新适配；
- 从 Claude Code 迁移到 ZCode 的会话（文件里带 `migrationSource: claudeCode`）在 Claude 和 ZCode 两侧各显示一条，是两条独立会话。

## 升级

**需要先升级服务端再升级客户端**：客户端把 agent 标为 `zcode` 上报，老服务端的枚举不认识会整批拒绝（400），ZCode 会话将完全不上榜。服务端升级会自动迁移 tasks / profiles / roles 表的 agent 约束，老客户端不受影响。

## 验证

- Rust 102 个测试通过，含 9 个 zcode 采集器单测（状态映射、去重、文件重写回退、历史回填、跳过后恢复）；
- 用本机 `~/.zcode/v2/sessions` 真实数据跑兼容性扫描，36 个近期会话全部解析成功；
- 服务端类型检查通过，新增 ZCode 事件与 409 拒绝用例（`npm test` 需 Docker Postgres，本机当时未运行 Docker Desktop 未跑成，待补）；
- 前端 `tsc --noEmit` 通过。
