# 0.5.8 通知两级过滤管线

服务端新增账号级通知过滤（Fast Path），解决「一多就吵」：完成、失败、时间提醒先过一遍程序规则，不该打扰的只入列不弹通知。等待授权和审批请求**永远提醒**（审批 30 分钟无人处理按拒绝处理，不能静音）。

## 规则（按顺序评估，任一命中即静音）

1. **agent 静音**：按 Claude / Codex / 豆包 / WorkBuddy 分别开关；只影响会话完成/失败事件，等待授权仍会提醒。
2. **免打扰时段**：按本地时间（时区偏移随开启时的设备自动填入）；开始等于结束视为全天。只静音勾选的类型（会话完成 / 失败中断 / 时间提醒），建议保留失败提醒。
3. **最低优先级**：会话事件取所有关联任务里的最高优先级（未关联任务按「中」），时间提醒按任务/目标自身优先级；达不到门槛的静音。

设置入口：设置页「通知规则（账号级）」，改动即时保存，对所有设备生效。

## 实现

- 服务端 `server/src/notify.ts`：`evaluateNotify`（Fast Path）+ `setSemanticFilter` 接缝（Slow Path，供以后接 LLM 语义判断，当前不启用）。表 `notify_settings`（每账号一行 jsonb）。
- 接入点：`POST /events` 的可通知事件、临时会话失败提醒、时间提醒广播与快照（提醒对象上带 `notify` 字段）。
- 客户端：桌面通知与 Android 前台服务对 `notify: false` 的提醒只入列不弹通知（重连后免打扰已过会照常补提醒）；设置页新增通知规则区块。
- 接口：`GET/PATCH /notify/settings`；WS 新增 `notify.settings` 广播（改设置时其它设备感知）。

## 任务的执行工具支持豆包 / WorkBuddy

任务详情的「执行工具」下拉从 Claude / Codex 扩到四项。豆包和 WorkBuddy 只做状态监听，所以只用于归类：选中后「开始执行」置灰并提示到客户端里执行，跑完用「关联已有会话」把会话挂到任务上；开始计时、关联会话、自动流转（会话完成 → 待验收）照常可用。任务列表的执行工具标记也改成显示真实名称（以前非 Claude 一律显示 Codex）。

## 已知限制

- Slow Path 未启用：现在全部规则都是确定性的程序规则。
- 优先级只看任务自身，未综合所属目标的优先级。
- 服务端测试的提醒用例依赖毫秒级定时器，在低负载差异下偶发超时（基线同样存在，与本次改动无关）。
