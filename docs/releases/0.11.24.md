# 0.11.24

修复「任务执行时发送的消息，等一会又出现一条」。

## 根因

会话详情页会自动从电脑拉一次原生 transcript 并**整段替换**服务端的消息记录（`replaceHistory`）。该函数在「有正在运行的 run」时会保留该 run 关联的消息（刚发的那条 user 消息、已流式落库的助手回复），随后又把 transcript 快照整段插入——transcript 里同样有这条消息，于是库里出现两份，界面就重放了。

## 修复

`server/src/db.ts` `replaceHistory`：保留 run 关联消息的同时，把 transcript 快照里与保留消息**对得上的副本**按 (role, 正文前 400 字) 多重集匹配跳过，对不上的（真正新增的）照常插入。这样：

- 任务运行中打开详情页同步历史，不再重放刚发送的消息 / 已显示的回复；
- transcript 里尚未出现的内容（流式进行中的回复）仍由保留的 run 关联消息兜底，不丢失；
- 真正的重复发言（「继续」说了两遍）不受影响——多重集按出现次数配对。

## 验证

- `tsc --noEmit`（server）通过；`npm test` 全过。
