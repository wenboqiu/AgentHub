# 0.11.29

豆包会话能读到对话正文了（读窗口）；发不出去的会话不再显示输入框。

## 新增

- **豆包对话流：改读客户端窗口**（桌面端，Windows）。豆包正文既不进 `sdk_storage\log`（只有生命周期事件和会话元数据），也不进 `IndexedDB`（只有应用配置和 persona），所以详情页一直是空的。现在改用 UI Automation 读豆包窗口里**已经渲染出来的**消息（`src-tauri/src/doubao_ui.rs`，新命令 `doubao_visible`）：
  - 走 `RawViewWalker` 的原始树——`FindAll` 只返回控制视图，`list_items` / `v_list_row` 这些布局容器不在里面。
  - 角色按行首容器类名判定（助手 `relative grid …`、用户右对齐气泡 `… container-xxxx`），认不出退回几何（内容起点偏右算用户）。
  - 正文取叶子 Text 按纵坐标拼行；豆包会把一句话拆成几个 span，包裹层 Text 名字为空要继续往下走；容器 Text 与子节点同名时，按「矩形更小且被包住」去重。
  - 跳过按钮子树（朗读 / 复制 / 推荐追问），并从最后一条「今天 HH:MM」时间行截断。
  - 定位对话区改成一次 `CreatePropertyCondition(Name=doc_editor)` + `FindFirst`（1.9s → 85ms），整轮读约 0.7 秒。
  - 会话页每 3 秒轮询一次（页面隐藏时跳过），消息以只读形式接在对话流末尾：没有时间、不能分支 / 评价 / 重发。

## 变更

- **只读会话不再渲染底部输入框**：豆包、WorkBuddy 都发不出消息，`footer.composer` 对它们整块不渲染（WorkBuddy 之前还能打字，其实也是白打）。
- 豆包会话隐藏「刷新电脑上的记录」按钮（该接口对豆包固定返回 409），并在会话页给出说明：正文字数、能读到几条、窗口是否停在别的对话上。
- 豆包的头部提示不再出现空白机器名，空状态文案换成「正文不落盘，只能读窗口，把豆包开着并停在要看的对话上」。

## 边界

- 只能拿到**窗口里当前挂着的那几条**：滚出视野的更早消息拿不到，要往前翻得在豆包客户端里滚一下。
- 豆包最小化 / 窗口被遮挡时元素矩形会空，这一轮读不到（下一轮自动恢复）。
- 豆包大版本改 DOM 类名时角色判定会退化成几何判断，可能把助手的气泡误判成用户。
- 豆包仍不支持远程发消息、新建、分支，也不读历史接口；继续对话回客户端。

- `cargo test --lib doubao_ui`：JSON 形状用例通过；`--ignored` 的本机实抓用例在豆包 2.34.6 上抓到当前对话 8 条消息，角色与正文正确。
- `cargo check` 通过（仅剩仓库原有的 dead_code 警告）、`tsc --noEmit` 通过、`npm test` 75 项通过。
- `session-preview` 截图确认：监听会话无输入框，普通 Claude 会话输入框仍在。
