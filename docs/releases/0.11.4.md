# 0.11.4 监听会话也有状态提示，项目页与发单表单改版

客户端换安装包即可；本版服务端另有改动（只读监听会话跑完先同步正文再攒任务单、收尾排队），一并先升服务端更稳妥。

- **只读监听会话也有状态行**：WorkBuddy / 豆包这类会话在服务端不建 run，对话页的「呼吸点 + 计时」过去只挂在活跃 run 上，所以它们运行中界面永远是空的。现在只要服务端说这次在跑，会话底部就有一行：`WorkBuddy 这一轮还没结束 · 14 秒前有新记录`，计时从进入运行态算起；超过 5 分钟没新记录改说「N 分钟没有新记录」，超过 30 分钟追加「可能已经停在那里」。这类会话拿不到 agent 的逐条活动，所以不编「思考中 / 执行中」。
- **项目页收起成一行**：项目列表默认折叠，一次只展开一条编辑；展开时才进「项目配置」，未保存会有标记。
- **项目配置改成「电脑 + 目录」**：一条配置 = 一台电脑（下拉，候选来自新接口 `GET /machines`：在线执行器 + 用过或手填的机器，在线优先）+ 该电脑下的项目目录；支持「任意电脑」「其他电脑…」手填，已占用的电脑在下拉里置灰。
- **发单表单**：项目配置合成一个下拉（`机器 · 路径`），可以不选、交给项目经理挑；「派给谁」不再列出项目经理。
- **只读会话的收尾顺序**：WorkBuddy 这类会话跑完，服务端先把这一轮正文同步进库、再生成处理意见，避免「任务单先冒出来、回复还停在上一轮」；客户端收到 `session.history` 时重载正在看的会话。

会话页的状态行与项目 / 发单改动都在客户端；同步顺序与收尾队列在服务端。
