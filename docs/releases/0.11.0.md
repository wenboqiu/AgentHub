# 0.11.0 一句话发单，项目经理先写完再派

这一版把「派活」的起点从任务列表搬到了看板：点「发新单」，先选项目，剩下的电脑、目录、人、正文都可以留空——单子会先落到项目经理手里，由它借电脑上的 agent 用模型补成一张能开工的任务单，你过一眼、改一改，确认了才真的派出去。

同一版里项目经理也从一个全局角色变成角色上的身份标记：可以有多位，各管一个项目或管所有项目。

## 发新单：只填人知道的那几格

看板页顶部新增「发新单」，表单顺序刻意如此：

```text
项目（必填） → 项目配置 · 电脑 / 目录（可空） → 派给谁 · 角色（可空） → 标题（必填） → 正文（可空）
```

- **项目决定材料和地方**：项目说明、最近几条任务结论会随单下发；项目登记的各机器目录成为电脑/目录的候选项；
- **留空不是没填**：电脑留空表示「按在线机器和项目目录挑一台」，角色留空表示「经理按角色清单挑人」，正文留空表示「经理按已知事实补目标 / 背景 / 交付要求」；
- **发单前先有经理**：没有任何项目经理时按钮直接禁用，服务端也会拒；选了项目后会显示这单归谁补写（本项目专属经理优先，其次管所有项目的）。

## 项目经理先写，人确认才派

发单不再 `createTask`，而是落成一张**待确认的任务单草稿**（`kind=ticket`，没有来源会话也能挂），看板顶部多出「待确认」区：

1. **落草稿**：`POST /tickets` 建草稿并立刻起一次细化；
2. **模型补写**：借你电脑上已登录的 agent（用项目经理角色的执行工具和模型），走的是意见细化同一条通道——服务端仍然没有模型凭据。给它的是一份专门契约：只能拿人那句话和项目说明/近况当材料，**不许编业务细节**，缺的信息写成「先确认 X 再动手」；项目锁定为你选的，电脑/目录你指定了就照抄，它不能把单子判废丢掉；
3. **卡片预览**：写完通过 WS 推回，卡片标「项目经理整理」，每个字段都能就地改；没写完时显示「项目经理正在读这张单…」；
4. **确认才派**：点「确认并派发」才建任务并按最终执行人开局（发单没有原会话可续，一律从零开跑）；点「只建任务」则交给自动派发按并发与每小时上限慢慢排。

电脑离线、没配经理角色时草稿也留着，卡片上可以点「让项目经理重写」。模型没写成、正文仍空的情况，派发前还有一层模板兜底（目标 / 背景 / 交付），保证执行端不会只拿到一个标题。

## 项目经理：角色上的标记，可以有多位

原来是「设置 → 项目经理 → 由谁担任」下拉，一个账号只能选一个。现在改成角色上的两个字段：

- **项目经理**：这个角色担任 / 不担任；
- **管哪些项目**：一个都不勾 = 所有项目；勾了就只负责这几个。

所以可以「阿岚管所有项目、阿青只盯农场」，也可以给每个项目各配一位。同一项目只允许一位专属经理，保存时直接拦下（409）。

挑人顺序写在 `pickManager` 里，发单、细化、自动派发三处共用：

```text
本项目专属经理 → 管所有项目的经理 → 只设了一位经理时由它兜底 → 都没有 = 没有负责人
```

自动派发也跟着改：不再是「一个全局经理派所有任务」，而是每个候选任务带着自己的 `project_id`，各自找管它那个项目的人；某个项目暂时没人管就跳过（不记失败、不占配额），等配好经理自然就会派。

## 顺手修的

- **空机器名排队**：项目目录登记成「哪台都行」而又有多台电脑在线时，派发会排进空机器名、永远等不到上线。现在会兜底取一台在线机器；
- **角色兜底链**：任务上的角色 → 派单经理给的建议 → 管这个项目的经理，三级都有才不会出现「有活没人干」；
- **自动派发候选**：放宽到「人直接发单」的任务（`auto_dispatch`），不再只认处理意见确认生成的那些。

## 升级

服务端有表结构改动，**先升服务端**（启动时自动迁移）：

- `roles` 加 `manager` / `manager_projects`；
- `session_proposals` 加 `kind='ticket'`（换 CHECK 约束）与 `machine` / `cwd`；
- `tasks` 加 `auto_dispatch`。

## 安卓包

- `AgentHub_0.11.0_arm64.apk`（6.0 MB，arm64-v8a 单架构，minSdk 24 / targetSdk 37，versionCode 11000）；
- 与 Windows 包同版本，覆盖安装 0.10.0 直接成功；仍为 debug 签名（未配正式 keystore），换正式签名前只能同签名覆盖装。

老库里在设置页选过的「项目经理角色」不会自动迁移成角色标记，升级后去「设置 → 角色」把那位角色勾成项目经理即可。

## 限制

- 补写要借一台在线的电脑和一个已登录的 agent，电脑没开就只能拿人的原话预览；
- 一位经理管一个项目是硬约束：想让第二个人也能补这个项目的单，得先撤掉前一位的管辖；
- 自动派发的并发与每小时上限仍按账号算（机器是同一台），不按项目拆分。
