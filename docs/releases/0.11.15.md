# 0.11.15 CodeBuddy 进角色，ZCode 与 mac 上的工具识别修好

角色里的「执行工具」多了一个 **CodeBuddy**；同时修掉一台装了 ZCode 的电脑在派活候选里被标成「没装 ZCode」的老问题，mac 上从访达启动时找不到 claude / codex 也一起解决。

- **新增 CodeBuddy 执行工具**：CodeBuddy 和 WorkBuddy 是同一份 CLI（npm 包 `@tencent-ai/codebuddy-code`），所以直接复用现有协议——新开会话、续聊、停止、批授权、读历史都通，会话列表里也能看到它的运行状态（监听 `~/.codebuddy/projects`）。没有独立登录态时先 `npm i -g @tencent-ai/codebuddy-code`，在终端跑一次 `codebuddy` 完成 `/login`。定位入口按「`CODEBUDDY_CLI` 环境变量 → npm 全局包 → PATH 各 prefix」找，跑脚本用的 node 也有兜底（PATH / Program Files / homebrew / nvm / volta，实在没有就借 WorkBuddy 的 Electron）。
- **ZCode 识别修复**：以前是扫 PATH 找 `zcode.exe`，但 ZCode 是桌面安装、从不把自己放进 PATH，于是装了 ZCode 的电脑上报的能力里没有 zcode，角色派活时被判成「没装」。现在改用执行器同一套安装定位（`Program Files\ZCode`），与服务端版本无关。
- **macOS 支持**：ZCode 安装位置补上 `/Applications/ZCode.app/Contents`（应用包内是 `Resources`，Windows 是小写 `resources`，两种都认），运行时用 `Contents/MacOS/ZCode` 走 `ELECTRON_RUN_AS_NODE`；Linux 也尽力找 `/opt/ZCode` 这类位置。
- **启动补齐 PATH**：从访达 / LaunchAgent 启动的 app，PATH 通常只有 `/usr/bin:/bin:/usr/sbin:/sbin`，既没有 homebrew 也没有 nvm、volta、`~/.local/bin`，`claude` / `codex` 因此既探测不到也 exec 不起来。现在启动时把这些目录**追加**到 PATH 末尾（只补缺的、不插队，你自己配的顺序不变），Windows 侧补 `%APPDATA%\npm` 与 nodejs 安装目录。
- **两处小修**：服务端派活校验改成统一的类型守卫（顺手修掉靠字符串比较做类型收窄的写法）；一条早就过期的测试（还在断言 WorkBuddy 只读）改用豆包。

服务端有改动（新增 `codebuddy` 的清单、角色与任务的列级 CHECK、派活校验），**先升服务端再升客户端**：老服务端会把上报的 codebuddy 过滤掉，角色里也选不到。
