# 0.9.8 WorkBuddy 能看完整对话了

0.9.4 起 WorkBuddy 在列表里只有状态、标题和摘要，点进会话流永远一句"暂不提供完整对话记录"。这一版补上读取通道：WorkBuddy 会话详情能看到和 Claude / Codex 一样的对话记录（仍是只读）。

## 怎么读的

WorkBuddy 本地 transcript（`%USERPROFILE%\.workbuddy\projects\<工作区>\<sessionId>.jsonl`）里正文齐全，只是之前没人读。打开会话详情或点刷新时，服务端向电脑端发 `history.request`，电脑端按 sessionId 在各工作区目录下找到对应 jsonl，解析最近 50 条消息回填入库：

- **消息行**：`type: message` 的 `user` / `assistant` 正文（`input_text` / `output_text`）；
- **时间戳**：WorkBuddy 用毫秒数字（Claude / Codex 是 ISO 字符串），解析时转回本地时间，日历跨度不会挤成一瞬；
- **注入块**：`system-reminder` 注入、`<user_query>` 派发包裹、`<cb_summary>` / `<task-notification>` 等纯注入消息全部剥离或跳过，与采集器标题提取同规则；
- WorkBuddy transcript 没有消息 id，`sourceId` / `branchPoint` 留空，评价与分支按钮会提示只读不支持，而不是误报"请刷新记录"。

服务端同时放开 `/sessions/:id/history` 对 workbuddy 的限制（豆包维持拒绝）。

## 限制

- 仍然**只读**：远程发消息、新开、分支、派活、等待授权都不支持——WorkBuddy 没有可用的执行通道，和之前一致；
- 读的是文件末尾 4 MiB，超长会话只展示最近的消息；
- 豆包不支持同样处理：它的对话内容存在服务端、本地不落盘（生命周期日志没有正文，IndexedDB 实测也没有），维持状态监听。

## 升级

客户端（电脑端 + 手机端）需要更新；服务端改动只是放开一个 409，老服务端配合新客户端也能读（新客户端发起的请求会先被旧服务端拒），建议一起升。先升服务端再升客户端。

## 验证

- Rust 106 个测试通过（新增 workbuddy 解析、注入剥离、毫秒时间戳、文件查找用例）；
- 前端 `npm run build` 与 node 测试 24 个通过；服务端 `tsc --noEmit` 通过。
