# 0.11.20 ZCode 审批优化：低风险请求不再弹卡

ZCode 跑任务时几乎每条命令都弹授权卡片，这次把不需要人看的挡在执行器本地。

- ZCode 的权限请求自带 `riskLevel` 风险标注。执行器现在按档位放行：默认只放行低风险（low），可调到「放行中低风险」或关闭；高风险（high）与致命（critical）永远弹卡，没标风险等级的也不放。
- 自动放行的请求会在会话时间线里留痕（「已自动放行（low 风险）：…」），事后能查。
- 设置入口：设置 → 本机执行与采集 → ZCode 自动放行。只影响 ZCode，Claude / Codex 的审批逻辑不变。
- 服务端代批（项目经理）不受影响，两者叠加：referee 先判，剩下的走本机快车道。
- 修了一个误报：WorkBuddy 桌面端把 CodeBuddy CLI 装在自己的 node 运行时目录（`~/.workbuddy/binaries/node/versions/<版本>/`）里，这个目录只存在于 WorkBuddy 注入的 PATH，AgentHub 的 GUI 进程看不到，于是派活页报「登记的配置所在电脑都装不了 CodeBuddy」。现在检测会主动扫这个位置，装过 WorkBuddy 的机器不再被误判。

只换客户端安装包即可。
