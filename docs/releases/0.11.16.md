# 0.11.16 WorkBuddy 退回监听，派活只留 CodeBuddy

角色的执行工具里不再出现 WorkBuddy，只保留 Claude / Codex / ZCode / CodeBuddy 四个。原因不是猜的，是实测的。

- **WorkBuddy 派不了单**：桌面端内置的 `lite-wb` bundle 用 `-p` 跑一轮就报 `Authentication required. Please use /login`；它没有独立登录态（要借桌面端桥接，隔离进程拿不到），也没有 TUI 可以自己 `/login`。
- **能派单的那份其实叫 CodeBuddy**：`@tencent-ai/codebuddy-code` 的 npm 完整版带 TUI，可以 `codebuddy` 登录一次，之后就能独立跑。两个入口本质是同一份 CLI，留在下拉里只会让人二选一选错。
- **老数据不卡住**：角色或任务里存着 `workbuddy` 的，派发时自动落到 `codebuddy`，不会报「请选择有效的执行工具」。
- **WorkBuddy 保留会话监听**：桌面端会话只有它能看（`~/.workbuddy/projects` 的标题、目录、运行中／完成状态、已读同步、只读历史），这部分照旧；只是不能从 AgentHub 往里发消息、新开或分叉了。
- **能力上报同步收敛**：服务端解析执行器上报的 `agents` 时只认派活清单里的工具，所以 `machines` 里不会再冒出「这台能跑 WorkBuddy」这种会误导人的条目。

服务端有改动（派活清单与校验、老数据降级），先升服务端再升客户端。

顺带说明：这台机器上 WorkBuddy 装在 `D:\Program Files\WorkBuddy`，而客户端的候选目录只有 `%LOCALAPPDATA%\Programs\WorkBuddy` 和 `%ProgramFiles%\WorkBuddy`（= `C:\Program Files`），所以 Rust 侧其实一直没认出来它——之前靠 `~/.agenthub/watcher/config.json` 里手写的 `workbuddyCli` 才跑得通。这次不再派活给它，这个盲区也就没有影响了。
