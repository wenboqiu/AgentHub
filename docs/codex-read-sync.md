# Codex 已读与 AgentHub 待处理同步

日期：2026-11-02。

原因：AgentHub 的 `acked` 原先只由自身的“已处理”按钮和新一轮运行更新。Codex 中看完回复、标记已读不会产生 rollout 生命周期事件，因此 AgentHub 一直保留旧的待处理提醒。

修复：电脑端每 15 秒只读核对 Codex Desktop 的版本 1 已读存储。完成／中止回复已读且连续两次核对一致时，上报带 `expectedAt` 和 `readAt` 的回执。服务端仅确认同账号、同机器、同一完成时间的那条提醒，不修改运行结果，不清除待授权事项。重复上报同一完成事件也不再重新打开已处理提醒。

本机适配已核实当前 Codex Desktop 的 `electron-thread-read-state-v1` 格式和默认本机执行器命名空间。使用本机 ChatGPT 登录身份的账号／用户声明计算命名空间；令牌不输出、不上传。若格式版本、账号、执行器命名空间不匹配，或文件缺失／解析失败，则保持原状态。自定义 WebSocket 执行器、API key 登录不在此次适配范围。只读存储属于桌面内部格式，升级后若发生变化应重新适配。

为防止旧已读信息清除新回复，核对还要求已读文件的保存时间晚于回复完成时间，且本机 rollout 最新生命周期与服务端完成时间完全相同。账号或 AgentHub 配置变化会重置连续核对状态。

只同步原始元数据声明由 Codex Desktop 创建的会话。CLI 创建的会话即使未出现在未读列表，也不能据此确认用户看过，仍需在 AgentHub 中处理。

验证：服务端 59 项测试通过，新增 4 项覆盖正常回执、旧版本回执、待授权保护、机器／账号隔离和重复完成事件。本地新增 5 项测试覆盖身份与版本、连续核对、未读、较新本机事件、过期快照和 CLI 会话保护。完整 Rust 回归中的命名管道测试在沙箱中失败，沙箱外复核通过，其余 63 项通过，1 项环境测试跳过；加入 CLI 保护后复测本次 5 项测试。

生效需更新服务端和 Windows 电脑端，Android 无需为此修复重新打包。更新后一般在两次轮询内清除已核实的旧提醒。尚未部署服务端、覆盖安装桌面应用或提交 Git；工作区内其他功能的并行改动保留。

交付文件位于 `artifacts.local/codex-read-sync/`：Windows 安装包、服务端更新源码包、独立源码快照及 SHA-256 校验清单。Windows release / NSIS 构建成功；此包包含本线程的回复操作和已读同步修复，未包含其他任务正在开发的功能。
