# 任务产物与项目近况

每个任务跑完留一份文档，每个项目滚动记一段近况。两件事共用一条链路：任务完成事件。

## 一、为什么不是「再存一份代码」

| 类型 | 例子 | 存哪 |
|---|---|---|
| 代码事实 | 目录结构、某个函数在哪 | **不存**。执行端在项目目录里自己读，比任何缓存都准，也不会出现两份事实 |
| 决策与结论 | 为什么用 SSE、迁移为什么走 advisory lock | **存**（项目近况、角色记忆、产物里的「风险与未决」） |
| 任务产物 | 这次改了什么、怎么验证、留下什么风险 | **存结论 + 指针**，不贴代码 |

判断标准：能用一条命令重新算出来的东西不上传，只能靠人记住的东西才上传。

服务端是唯一数据源，桌面端只是 UI + 采集器，所以「跨设备同步」不是选项，是既成事实；要定的是粒度。

## 二、任务产物

### 什么时候生成

| 触发点 | 行为 |
|---|---|
| 会话完成（`/events` 的 `done`，经 `syncTask`） | 生成/重建骨架，WS 推 `task.artifact` |
| 任务被手动推进到 `review` / `done` | 同上（不依赖会话事件） |
| 打开任务详情发现没有产物 | `GET /tasks/:id/artifact` 兜底补一份 |

### 六段结构

`做了什么 / 怎么验证 / 影响面 / 验收要点 / 后续 / 风险与未决`。

- 做了什么：执行端最后一次回复（最多 3000 字，从消息表重取，不用摘要里那 500 字段）
- 怎么验证：会话里摘出的证据（命令、测试、文件、截图、日志）
- 影响面：证据里的文件变更清单
- 验收要点：任务检查项及勾选状态
- 后续：没勾上的检查项
- 风险与未决：失败/停止的执行、未完成项、缺测试证据时明确写出来

材料缺失时写「待补」而不是留空——空段看不出是没做还是漏了。

### 覆盖规则

- `source='digest'`：服务端按材料生成，任务再次进入待验收时会重建
- `source='user'`：人改过，之后自动重建**不再覆盖**；要覆盖必须显式「按最新会话重建」（界面会二次确认）
- `source='agent'`：预留给执行端按契约自己交的版本，覆盖骨架

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/tasks/:id/artifact` | 读产物；没有就补生成。返回 `{artifact, path}`，`path` 是建议导出路径 `docs/tasks/<id>-<slug>.md` |
| PATCH | `/tasks/:id/artifact` | 改 Markdown，标记为 `user` |
| POST | `/tasks/:id/artifact/rebuild` | 按最新材料重建；`{force:true}` 才覆盖人改过的 |
| DELETE | `/tasks/:id/artifact` | 删掉，下次完成会重新生成 |

导出不占服务端带宽：前端拿 Markdown 直接 `Blob` 下载，文件名取服务端给的 `path` 的末段。默认**不**自动写回仓库——每次都提交 `docs/tasks/` 会把 git 历史淹没。

## 三、项目近况

`projects.brief` 是「这个项目是什么」（人手写、长期不变）；`project_brief_entries` 是「最近发生了什么」（机器追加、滚动淘汰）。

- 任务完成时追加一句：`「任务标题」+ 收尾回复的第一句有信息量的话`（去掉代码块，最多 240 字）
- 同一任务只记一条（`(user_id, project_id, task_id)` 的部分唯一索引），重进待验收不会重复
- 每个项目最多留 60 条，超出按时间淘汰
- 派活时 `recentBrief()` 取最近 8 条、最多 800 字，作为 `【项目近况】` 注入系统提示，排在 `【项目背景】` 之后、`【已知经验】` 之前
- 可在「设置 → 项目」里手写一条或删掉写错的

注入预算（`composeInstructions`）：准则 2000 → 项目背景 1500 → 项目近况 800 → 经验占剩余空间。近况是动态内容，所以给它固定上限，避免旧内容把经验挤掉。

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/projects/:id/brief` | 最近 60 条，时间倒序 |
| POST | `/projects/:id/brief` | 手写一条，`{text}`，最多 240 字 |
| DELETE | `/projects/:id/brief/:entryId` | 删一条 |

## 四、数据表

```sql
task_artifacts(user_id, task_id, kind='doc', md, source, created_at, updated_at)
  主键 (user_id, task_id, kind)；FK 到 tasks(user_id,id) ON DELETE CASCADE

project_brief_entries(id, user_id, project_id, text, task_id, created_at)
  唯一索引 (user_id, project_id, task_id) WHERE task_id IS NOT NULL
```

## 五、没做的

- **执行端交付契约**：派活时把「结束时交一个 JSON/Markdown 块」前置，让 agent 自己写产物。等骨架稳定后再开，否则接口和契约要一起改。
- **产物写回仓库**：保持手动导出。
- **按产物做检索**：现在只能按任务查；跨任务的语义检索要等产物积累出量再说。
