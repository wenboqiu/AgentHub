# 代批：会话等授权时，先让项目经理判断

会话卡在 `waiting` 有两种来源，能做的事完全不同，先分清：

| 来源 | 有没有回话通道 | 能不能自动继续 |
|---|---|---|
| AgentHub 派发的 run（Claude / Codex / ZCode 走 `--permission-prompt-tool stdio` 或 RPC） | 有。`approval.decide` 发回执行器，agent 立刻继续 | 能 |
| 你在终端里自己开的会话（含 AgentHub「在终端打开」） | 没有。stdin 在那个交互进程手里，服务端插不进去 | 不能，只能提醒你去终端 |

本文说的代批只覆盖第一种。第二种在界面上仍然按原样通知你，并提供「在终端打开」入口——不假装能替你点。

## 分层判定

审批里混着两个性质不同的问题，混在一起才显得规则「太笨」：

| 问题 | 谁更擅长 | 为什么 |
|---|---|---|
| **能不能做**（客观安全） | 规则 | `rm -rf`、写 `.env`、越界写——任何上下文都不能让它们变安全。规则确定、0 延迟、可单测、不受 prompt 注入影响 |
| **该不该做**（主观意图） | 有项目上下文的人 / 项目经理 | 装个包、联网拉数据、推一次远端：危险吗不一定，但「这个任务现在该不该做」只有上下文知道 |

所以每条裁决都带一个 `tier`，把「这条为什么轮不到规则定」标出来：

| tier | 含义 | 现在怎么处理 |
|---|---|---|
| `allow` | 规则看懂且安全 | 当场放行（快车道，不烧 token、不让人等） |
| `danger` | 硬红线，上下文不能让它变安全 | 必须人看，**项目经理也不能推翻** |
| `gray` | 风险取决于任务意图 | 交给人；将来只有这一类值得叫醒项目经理 |
| `unknown` | 规则看不懂 | 交给人，不让机器猜 |

```
run.approval 事件
      │
      ├─ 项目经理没开代批 ────────────→ 弹给你（和以前一样）
      │
      ├─ 落在任务边界内 / 规则看懂且安全 ──→ 直接 allowed + 通知执行器继续（不弹通知）
      │
      └─ 硬红线 / 边界外 / 看不懂 ───→ 把层级和理由挂到这条审批上，弹给你
```

**只会放行，不会拒绝。** 拒绝会打断 agent、而且误判的代价比慢一点大得多，所以 `deny` 始终留给人。
判不准就交回给人，不存在「兜底放行」。

## 规则表

判定顺序：先看硬红线，再看任务边界，最后看类型。任一段危险，整条命令就交给人（`a && b` 不会被 `a` 的安全背书）。

| 判定 | 结果 | tier | 说明 |
|---|---|---|---|
| `userInput`（agent 向你提问） | 交给人 | unknown | 这是需求决策，不是权限问题 |
| `rm`、`git reset --hard`、`git clean -fd`、`git push --force` | 交给人 | danger | 不可逆 |
| `DROP TABLE`、`TRUNCATE`、发布包、提权、下载即执行 | 交给人 | danger | |
| 越出项目目录的读写、重定向到项目外 | 交给人 | danger | 边界以会话的 `cwd` 为准 |
| `.env`、`.ssh/`、`*.pem`、`credentials` | 交给人 | danger | 读写都拦 |
| `node x.js`、`python x.py`、`sed -i`、`awk`、`find -exec` | 交给人 | unknown | 内容是任意代码 |
| MCP 工具、不认识的工具名 / 命令 | 交给人 | unknown | 它什么都能做 |
| `git push`（不带 force） | 交给人 | gray | 任务可能就是要推 —— 边界里声明过就放行 |
| `npm install`、`curl`、`ssh` | 默认交给人 | gray | 全局开了联网或任务声明就能放 |
| `npm run <自定义脚本>` | 交给人 | gray | 项目自己的脚本，内容不可预判 |
| 写到任务边界外的目录 | 交给人 | gray | 只在任务声明了 `paths` 时出现 |
| 只读命令（`ls`/`cat`/`rg`/`git status`/`git diff`…） | 放行 | allow | 可关 |
| 项目内写文件（`Write`/`Edit`/`mkdir`/`cp`/`git add`/`git commit`） | 放行 | allow | 可关，仍受边界约束 |
| 测试与构建（`npm test`/`npm run build`/`tsc`/`go test`） | 放行 | allow | 可关；`npm run <不认识>` 不放 |

`fileChange`（Codex）按每行一个文件逐个查边界；`Write`（Claude）的 detail 是「路径\n内容」，只取第一行——否则内容里的任意一行都会被当成路径。

## 任务执行边界（`tasks.constraints`）

派活时就定下「这个任务预计要碰哪」，比每条审批临时去问模型更准、更快、也可解释。

```json
{ "paths": ["server/src"], "net": true, "push": false, "scripts": false, "note": "只动服务端" }
```

- `paths` 非空即**收窄**：写到这些目录之外 → `gray`（交给人）；空 = 整个工作目录。
- `net` / `push` / `scripts` 是**授权**：为 true 时对应动作直接 `allow`，不必再开全局策略。
- 硬红线永远优先：边界写了 `net: true` 也不等于能 `git push --force`、能删库、能读 `.ssh`。
- 声明来源：项目经理出任务单时一并给出（`REFINE_CONTRACT`），建任务后落在任务上；任务详情页可手改。
- 派发时把这段边界拼进系统提示（`boundaryLine`），agent 一开始就知道自己能做什么，少撞墙。

## 数据与接口

`approvals` 加四列：

| 列 | 含义 |
|---|---|
| `decided_by` | `user`（人点的）/ `manager`（代批） |
| `decision_rule` | 命中或拒绝的规则 id，如 `read`、`dangerous`、`write-guard` |
| `decision_reason` | 一句话理由，界面直接显示 |
| `decision_tier` | `allow` / `danger` / `gray` / `unknown`，界面用它标「硬红线 / 边界外 / 规则看不懂」 |

待处理时 `decision_reason` 也会写——表示「项目经理看过了，因为什么没敢批」，审批卡上显示在你点按钮之前。

配置在 `dispatch_manager`（一个账号一份）：

| 列 | 默认 | 含义 |
|---|---|---|
| `approve_enabled` | false | 代批总开关，与自动派发独立 |
| `approve_read` | true | 只读命令 |
| `approve_write` | true | 项目内写文件 |
| `approve_tests` | true | 测试与构建 |
| `approve_network` | false | 联网 |
| `approve_per_hour` | 60 | 每小时代批上限，超了全部回到人手上 |

开启代批必须有项目经理角色——谁放的行要能追到人。

## 护栏

1. **先给执行器发 `approval.created`，再发 `approval.decide`**：顺序反了执行器只能走「迟到的裁决」分支，虽然兜住了，但没有必要冒这个险。
2. **执行器断线就回滚**：`decide` 之后 `sendExecutor` 失败，把记录退回 `pending` 并交给人，绝不留一条「已放行」而实际没人继续的记录。
3. **并发只认一个赢家**：`UPDATE ... WHERE status='pending'` 是闸门，人点和代批同时发生时后到的那个拿不到行，直接放弃。
4. **每小时配额**：代批次数超限后全部交给人。这是防 agent 跑飞的最后一道闸。
5. **留痕**：代批成功后往会话里插一条 `approval` 消息（「项目经理已放行：Bash npm test（测试与构建）」），时间线里能看出是谁批的。
6. **边界不放宽硬红线**：`grants` 只在 `danger` 检查之后生效——这是「授权」与「安全」的分界线，顺序不能反。

## 没做的

- **模型档（灰色地带交给 LLM 判）**：还没做。现在 `gray` 只是被标出来，仍然交给人。要做的前提是先有真实分布——很可能任务边界写清楚之后，`gray` 的量已经小到不值得为它跑一次模型。
- **自动拒绝**：见上。
- **经验学习**：「同一命令你批过三次就自动放行」听着好，但会让边界随历史漂移，出事时说不清是哪条规则放的行。
- **终端会话代答**：没有回话通道，做不了。
- **项目经理自己改边界**：现在只有出任务单时声明一次 + 人手工改；执行中「因为遇到边界才需要放宽」还得人点。
