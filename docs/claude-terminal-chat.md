# 在原 Claude Code 终端会话中继续聊天

## 行为

- 在 AgentHub 的 Claude 会话页发送消息时，如果原终端仍然打开，桌面执行器通过该会话的本机收件管道投递；原终端继续执行，消息和回复进入同一份原生记录。
- 原终端已经关闭时，继续使用已有的 `claude -p --resume` 方式。
- 原终端回复会同步回 AgentHub。只有在原生记录中确认接收到本条消息后，才跟踪后续回复；不会把之前正在生成的回复当成本条消息的结果。
- 原终端仍保留权限控制。接收规则要求批准时，需要在原终端批准；投递后 5 分钟仍未确认接收，会显示未确认，不自动重复投递。
- 已接入原终端的运行按钮显示“停止跟踪”。它只结束 AgentHub 的跟踪，不终止用户打开的终端；授权和中断操作在原终端处理。
- 同时在原终端输入另一条普通消息时，结束本条消息的回复归属跟踪，刷新原生对话记录仍可查看完整上下文。
- Windows 版本优先支持。终端未发布收件地址、认证信息缺失或多个终端持有同一会话时给出明确错误，不启动另一个进程写同一份会话。

## 本机边界

原有账号鉴权、电脑在线和目录黑名单检查继续生效。收件地址必须是本机 Windows 命名管道，且来自 `claude agents --json` 返回的活跃进程，对应会话 ID 与项目目录必须匹配。使用该管道对应的 peer key 做认证；key 不进入服务端、日志或 UI，也不声明自己拥有绕过终端权限的模式。

参考 [Claude Code 本机会话收件接口](https://code.claude.com/docs/en/cross-session-messaging#the-sessions-inbox-socket)。原终端通常将外来消息显示为 AgentHub 的消息预览，斜杠命令按普通文本处理。

## 验证

- Rust 单元测试覆盖会话/项目/活跃进程匹配、消息转义、分段 JSONL、回复关联和 Windows 命名管道读写。
- `cargo test --lib` 58/58 通过，包含 Windows 原生管道中文消息测试与刷新历史保留输入回归；`npm run build` 通过。
- `server/tools/verify-claude-terminal.mjs` 使用真实 Claude Code CLI 2.1.292 和仅本机监听的模拟 Messages API；临时会话禁用 hooks 和工具，避免测试数据上报用户的 AgentHub，也不调用真实模型。
- 实测两轮调用发生在同一个 CLI 进程与会话：第一轮为种子回复，第二轮通过该会话的认证命名管道投递；原生 JSONL 保存了指定消息 UUID、回复以及 `end_turn`，验证通过。
- 此验证使用无头 CLI，尚未用用户现有交互终端做端到端测试。

此功能复用现有服务端远程消息协议；需要更新桌面执行器和前端才能生效。
